## Блок E — Дашборд-центр (★★★)

- [ ] **E2.** Быстрые действия на дашборде: кнопки «+ Task», «+ Idea», «+ Plan» с мини-диалогом (title → Enter → создано)
- [ ] **E3.** Дневник самочувствия: кликабельное сердце на дашборде → шкала настроения 1-5 (эмодзи) + заметка. Миграция `wellbeing_entries` (mood_score 1-5, note). График настроения за 7 дней (mood-chart).
- [ ] **E4.** Фокус-задача (MVP): таблица `focus_tasks` (одна задача на юзера). Выбор из Today's Tasks → виджет на дашборде → кнопка «Start Focus» → отдельная страница `/focus` с таймером 25 мин (клиентский). Pause/Stop. Минимальный UI — только задача + таймер.

## Блок J — Геймификация 2.0 (★★★)
- [ ] **J1. Boss-битвы** — крупные планы → «босс» со шкалой HP = кол-во шагов. Шаг выполнен = удар по HP. Победа (все шаги done) = ачивка + XP-множитель ×1.5. Визуально: карточка плана с HP-баром в стиле RPG.
- [ ] **J2. Дерево навыков** — три ветки: «Продуктивность» (задачи), «Фокус» (P1-задачи, стрики), «Дисциплина» (регулярность). Разные действия качают разные ветки. Визуализация на вкладке «Прогресс» (объединить с F1).

## Блок K — Аналитика (★★☆)
- [ ] **K1. Heatmap продуктивности** — GitHub-style сетка на дашборде: цвет ячейки = кол-во закрытых задач в день. Годовая и месячная шкала. Данные уже есть в БД (tasks.completed_at).
- [ ] **K2. Разбивка по тегам** — круговая диаграмма или stacked bar: распределение времени/задач по категориям. Помогает понять, куда уходит фокус.
- [ ] **K3. Оценка времени** — поле `estimatedMinutes` на задаче. В дашборде — «запланировано на сегодня: 6.5 ч из 8». Предупреждение при перегрузке (>8h). Миграция: `ALTER TABLE tasks ADD COLUMN estimated_minutes INT`.

## Блок L — Интеграции (★★★)
- [ ] **L1. Telegram-бот: создание задач** — команда `/task Купить молоко p2` → парсинг: title, priority, опционально dueDate. Задача создаётся в Questify. Бот уже есть (`src/app/api/telegram/route.ts`) — расширяем парсером команд.
- [ ] **L2. Google Calendar sync** — односторонняя: задача с dueDate → событие в Google Calendar. OAuth-подключение аккаунта в профиле. Миграция: `user_integrations` таблица для хранения токенов.

## Блок M — AI (post-MVP) (★★★)
- [ ] **M1. AI-декомпозиция планов** — ввод «Хочу запустить блог» → AI генерирует структурированный план с шагами через Plans API.
- [ ] **M2. AI-приоритизация** — утренняя рекомендация на дашборде: «Сегодня лучше взяться за X (дедлайн завтра), Y можно отложить».
- [ ] **M3. AI-рефлексия** — саммари дня/недели на основе паттернов выполнения: что получилось, что нет, тренды.

## Блок N — Комментарии к задачам (★★☆)
- [ ] **N1. Таблица `task_comments`** — миграция: `id, task_id (FK→tasks), user_id (FK→auth.users), content TEXT, created_at, updated_at`. RLS: юзер видит комментарии к своим задачам. Мягкое удаление? Пока без (MVP — только create/read).
- [ ] **N2. Серверные экшены** — `createComment(taskId, content)`, `getComments(taskId)` (сортировка по created_at ASC). Revalidate: `/tasks/[id]`.
- [ ] **N3. UI на странице задачи** — под описанием задачи — список комментариев (автор, время, текст). Поле ввода + кнопка Send. Оптимистичный UI при добавлении.
- [ ] **N4. Бейдж на карточке задачи** — если есть комментарии, показывать иконку 💬 + количество на TaskCard и KanbanCard (опционально, можно без бейджа в MVP).

## Блок O — Тематические флоу (★★★)
- [ ] **O1. База flows** — миграция: `flows(id UUID PK, user_id FK→auth.users, name TEXT, theme_key TEXT, created_at)`. Поле `flow_id` nullable на `tasks`, `plans`, `ideas`. Переключатель флоу в сайдбаре/хедре. Фильтр «только этот флоу» на досках и списках. Каждый флоу — своя цветовая схема через CSS-переменные.
- [ ] **O2. Sci-Fi dev-флоу** — предустановленный флоу для админа. Roadmap sync: парсер `roadmap.md` → извлечение `[x]`/`[ ]` пунктов с ключами (A1, B2…) → upsert в БД по полю `roadmap_key`.
- [ ] **O2a. XP за выполненные пункты** — при синке: обнаружен новый `[x]` → `awardXp()` (если `xp_awarded = false`). Миграция: `ALTER TABLE tasks ADD COLUMN roadmap_key TEXT UNIQUE`, `ADD COLUMN xp_awarded BOOLEAN DEFAULT false`.
- [ ] **O2b. Sandbox → воронка идей** — пользователь кидает идею в песочницу dev-флоу. Sisyphus подхватывает, анализирует («что это могло значить в контексте проекта»), кладёт в блок Z (неразобранные идеи). Дальше — диалог: вместе уточняем, докручиваем, после чего идея либо попадает в роадмап, либо отбрасывается. Медленно, но осмысленно.
- [ ] **O2c. Кнопка «Sync Roadmap» в профиле** — заменяет текущий Seed Roadmap. Запускает парсинг + дифф + upsert. Идемпотентно, без дублей.
- [ ] **O2d. Доступ в dev-флоу** — `is_admin BOOLEAN` на `profiles` (ставится в БД вручную). Если `true` → в профиле появляется скрытая кнопка «Join the crew». Нажатие → визуальный эффект (неон/глитч) + разблокировка Sci-Fi dev-флоу. Технически — флаг, UX — ритуал.
- [ ] **O3. Форма обратной связи** — страница `/feedback` (или секция в профиле). Поля: заголовок, описание, тип (idea/problem). Отправка → создаёт идею в dev-флоу во вкладке «Feedback». Доступна всем залогиненным пользователям.
- [ ] **O4. Fantasy flow (заглушка)** — метка для будущего семейного флоу (переезд). Пока без реализации — просто резерв `theme_key = "fantasy"` и место в UI. Мульти-юзер доступ — отдельная тема (продолжение блока G).

## Блок Z — Неразвитые идеи (черновик)
> Идеи, которые звучат интересно, но требуют проработки или ждут своей очереди.

- [ ] **Z1. Ежедневные квесты** — 3 случайные цели на день из пула правил (закрой N P1-задач, отметь M шагов плана и т.д.), +бонус XP. Идея понятна, но требует проработки пула правил и UI-виджета.
- [ ] **Z2. Webhook-система** — пользователь указывает URL → Questify шлёт HTTP POST при событиях (task.completed, plan.finished, streak.updated). Открывает автоматизации через Zapier/n8n/Make: уведомления в Slack, синк с Notion, кастомные триггеры.

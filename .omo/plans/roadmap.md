## Процесс (см. AGENTS.md → AGENT WORKFLOW)

> Пет-проект, свободное время. Режим сессии выбирается под окно возможностей.

### Три режима сессии

| Режим | Окно | Что умещается |
|---|---|---|
| ☕ **Короткая** | 30 мин | 1 багфикс, 1 мелкая фича, ревью кода, чистка слопа |
| 🔧 **Нормальная** | 1–2 ч | 1 средняя фича, планирование + реализация, TDD-цикл |
| ⚡ **Марафон** | 3+ ч | Закрытие блока, крупная фича, рефакторинг, миграции |

### Старт сессии (1 минута)

```
"ulw Что у нас по HANDOFF? Покажи статус."
```
→ Агент читает HANDOFF.md, показывает незакрытые задачи, предлагает с чего начать.

### Сценарии по режимам

#### ☕ Короткая сессия (30 мин)

```
ulw → delegating (quick/deep) → Lefthook → commit → push
```

Без metis/hyperplan/momus — только исполнение. Примеры:
- `"ulw fix: почини баг с отображением backlog separator в Safari"`
- `"ulw /remove-ai-slops только для lib/actions/plans.ts"`
- `"ulw добавь индексы для get_dashboard_data в миграцию 00011"`

#### 🔧 Нормальная сессия (1–2 ч)

```
ulw → metis (если есть неясности) → delegating → /visual-qa (если UI) → Lefthook → commit → push
```

Примеры:
- `"ulw metis: разбери требования к блоку N1 — таблица task_comments, RLS, server actions"`
- `"ulw visual-engineering: сделай компонент TaskCommentList — мобильный first, Tailwind, тёмная тема"` → `/visual-qa`
- `"ulw deep: напиши тесты для lib/gamification/engine.ts — awardXp, completeTask с моком Supabase"`

#### ⚡ Марафон (3+ ч) — раз в 1-2 недели

```
ulw → metis → hyperplan → momus → /start-work → /remove-ai-slops → /review-work → commit → push
```

Только для крупных задач: закрытие блока, новая архитектура, сквозной рефакторинг.
Пример: `"ulw Закрываем блок N. metis: разбери все 4 подзадачи."` → `hyperplan` → `momus` → `/start-work block-n`

### Когда какой агент (по убыванию частоты)

| Инструмент | Как часто | Для чего |
|---|---|---|
| `ulw` | **Каждая сессия** | Активирует ultrawork-режим в первом сообщении |
| `visual-engineering` | Каждая UI-задача | Вёрстка, стили, анимация — всегда делегировать |
| `/visual-qa` | После каждого UI-изменения | Скриншот → oracle pass/fail |
| Lefthook | Перед каждым коммитом (авто) | `lint` + `type-check` параллельно |
| `/ralph-loop` | Длинные задачи (перед уходом) | Оставить агента работать на 20-40 мин без присмотра |
| `/remove-ai-slops` | Раз в неделю / после блока | Чистка AI-паттернов в изменившихся файлах |
| `/debugging` | При 3-fix-stop | Hypothesis-driven root cause analysis |
| `metis` | Перед средней/крупной фичей | Gap-анализ, поиск ambiguity |
| `hyperplan` | Только марафон | 5 adversarial agents для критичных решений |
| `momus` | Только марафон | Формальная верификация плана |
| `/review-work` | Закрытие блока | 5 параллельных проверок |
| Context7 | По необходимости | Актуальная документация Supabase/Next.js/Tailwind |

### Финиш сессии (1 минута)

```
"ulw Обнови HANDOFF.md: что сделано, что в процессе, что дальше. Проанализируй паттерны этой сессии и добавь блок «Рекомендации по процессу». Commit + push."
```
→ Агент обновляет HANDOFF.md, добавляет анализ стиля работы (fix:feat, каскады, проблемные зоны) с конкретными предложениями, коммитит, пушит. Сессия закрыта чисто.

**Что попадает в «Рекомендации по процессу»:**
- fix:feat ratio за сессию и тренд (растёт/падает)
- Были ли fix-каскады (3+ подряд) — причина
- Использовались ли гейты (/visual-qa, Lefthook) или были пропущены
- Какие агенты использовались, какие стоило бы
- Одна конкретная рекомендация на следующую сессию

### Правило 3-fix-stop (без изменений)

3 fix-коммита подряд на одну задачу → `/debugging` → root cause analysis.

### Запрещённые паттерны (дорого стоят на пет-проекте)

- ❌ 4+ проблемных областей в одной сессии (6 июля: 68 коммитов, Matrix+Kanban+mobile+CI → каскад багов)
- ❌ Визуальная фича без `/visual-qa` (mood chart: 12 fix-коммитов вместо 1-2)
- ❌ Марафон без `hyperplan` для сложной архитектуры (Matrix: 14+ fix-коммитов)
- ❌ Оставлять сессию без `commit + push + HANDOFF` (через 3 дня забываешь контекст)

### Раз в неделю — аудит процесса (15 мин)

В конце недели (или когда накопилось 3+ сессии) — короткий аудит:

```
"ulw Еженедельный аудит разработки Questify:

1. Проанализируй логи этой недели (git log --since='7 days ago' --oneline):
   - fix:feat ratio, тренд относительно прошлой недели
   - Были ли fix-каскады, какие гейты пропущены
   - Самые проблемные модули (по числу fix-коммитов)

2. Проверь внешние рекомендации (librarian):
   - Новые фичи OMO (oh-my-openagent changelog, PR'ы)
   - Новые скиллы в opencode (какие появились, какие стоит попробовать)
   - Стоит ли сменить модель какому-то агенту (появились ли stronger/cheaper альтернативы)

3. Выдай:
   - 1-3 конкретных изменения в AGENTS.md или roadmap.md
   - Нужно ли обновить oh-my-openagent.json (модели агентов, fallback-цепочки)
   - Оценка: стало лучше чем на прошлой неделе? (да/нет/так же)"
```

**Что попадает в аудит:**
- Недельная статистика: коммиты, fix:feat, каскады, гейты
- Внешние изменения: новые OMO-фичи, модели, скиллы
- Конкретные предложения: сменить модель агенту, добавить скилл, поправить воркфлоу
- Вердикт: улучшился процесс или нет

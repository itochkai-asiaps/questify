# План аудита и рефакторинга Questify

> Приоритет: 🔴 высокий — после закрытия блока D
> Цель: выявить архитектурные проблемы, накопленный техдолг, потенциальные баги

---

## Этап 1: Архитектурный аудит (oracle)

**Что проверяем:**
- Связность Server Actions (10 файлов в `src/lib/actions/`) — дублирование, несогласованность
- Состояние: Zustand (5.0) vs React state vs Server Components — нет ли конфликтов
- RLS-политики: все ли таблицы защищены, нет ли утечек между пользователями
- Типы: Zod на границах — везде ли? Нет ли пропущенных валидаций
- revalidatePath: корректно ли инвалидируется кеш после мутаций

**Файлы для анализа:**
```
src/lib/actions/*.ts          (10 файлов — все Server Actions)
src/types/task.ts             (Zod-схемы)
src/types/plan.ts
src/hooks/useAuth.ts          (критичный — lastUserId ref)
supabase/migrations/          (9 миграций — идемпотентность)
```

**Ожидаемый результат**: список архитектурных проблем с приоритетами

## Этап 2: Блок D — Kanban (приоритетный)

**Проблемные места (известные):**
- `kanban/page.tsx` — ~400+ строк, DndContext + handleDragEnd + optimistic state
- `kanban-card.tsx` — useSortable, возможны конфликты transforms
- `tasks/page.tsx` — split-view + backlog + D&D — сложная композиция
- D6: новый код от трёх параллельных агентов — нужна сверка

**Что проверять:**
- D&D: нет ли утечек памяти (listeners, sensors)
- Optimistic UI: корректный откат при ошибке сервера
- Backlog: статусы не теряются при D&D между секциями
- Мобилка: split-view не ломается на малых экранах
- Edge cases: пустой Kanban, одна колонка, 50+ задач

## Этап 3: Блок E — Дашборд

**Проблемные места (известные):**
- `dashboard/page.tsx` — 680 строк, один файл
- Mood chart: 9 fix-коммитов, визуальные баги
- HP-бар: курсорный трекинг (20 зон), производительность
- `/focus` — таймер, нет персистентности сессий

**Что проверять:**
- Дашборд: декомпозировать ли на меньшие компоненты?
- Mood chart: рендерится ли корректно при 0 данных?
- HP-бар: не дёргает ли ререндеры при движении мыши
- E0 (быстродействие): почему дашборд грузится долго — профилировать

---

## Этап 4: Блоки A-C (облегчённый)

**Проверяем:**
- Геймификация: XP-начисления не теряются при edge cases
- Конвертация сущностей: idea→task, plan item→task — не теряются ли данные
- Тёмная тема: все ли компоненты корректны в обоих режимах

## Методология

| Инструмент | Для чего |
